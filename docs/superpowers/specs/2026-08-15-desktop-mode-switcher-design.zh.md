# 桌面模式切换器设计

[English](2026-08-15-desktop-mode-switcher-design.md) | 中文

## 范围

桌面应用在一个窗口中提供 `DeepSeek Chat` 与 `Harness` 两种可选体验。模式选择器位于操作系统已有的标题栏内：macOS 上紧跟红黄绿按钮，Windows 上位于标题栏左端。它不增加应用自有标题区或全宽工具栏。

两种模式保留各自的认证、会话存储、导航和页面状态。主题偏好是两者之间唯一同步的产品偏好。除此之外，选择模式只改变可见性，不会复制或转换页面数据。

## 用户体验

模式控件是一个紧凑的双分段切换器，左侧标记 `Chat`，右侧标记 `Harness`。两个分段等宽，选择任一分段都会直接切换模式，不会打开菜单。控件没有下箭头或产品图标。浅层的主题匹配轨道与滑动高亮用于标识选中分段，不绘制外框描边。

在所有受支持的窗口宽度下，切换器都保持 164px 宽、32px 高，标签绝不收起为图标或缩写。亮色模式使用深色文字和浅色选中高亮；暗色模式使用浅色文字和深色选中高亮。悬停、按下和键盘焦点状态保持清晰，且不会改变控件尺寸或移动周围的标题栏内容。

切换器使用 `radiogroup` 和 `radio` 语义，两个分段都带有 `aria-checked`。`Tab` 聚焦控件组，`Left` 和 `Right` 选择相邻模式，`Home` 和 `End` 选择首尾模式。用指针点击任一标签都会立即选择对应模式。

Chat 专属的重新加载和清除数据操作继续使用切换器右侧独立的 32px 溢出控件。执行命令、收到外部指针输入或按下 `Escape` 后，该菜单关闭。

切换器属于窗口 chrome，而不是任一产品导航栈内的控件。Harness 保留已有的内部标题栏适配。Chat 只避让操作系统标题栏，因此官网页面会在该行下方立即按原始侧栏和页首布局开始。产品内容不占用额外的全宽分隔线、工具栏或空白标题区。

## 窗口分层与几何

本地 Electron 外壳继续负责 IPC、模式状态、重试操作、失败消息、标题栏底色，以及操作系统标题栏内未被控件占用的可拖拽区域。Harness 继续使用完整窗口内容边界，因为自身布局已经适配该标题栏。Chat 内容从 44px 标题栏高度下方开始，并使用所有剩余窗口空间；它不会再为模式切换器增加第二层 inset。

透明的本地 mode-chrome WebContentsView 位于两个内容视图之上。Harness 模式下，它紧密匹配 164px 切换器；Chat 模式下，它还包含 4px 间距和 32px 溢出控件。它只会为 Chat 操作菜单向下扩展；只有清除数据的模态对话框会覆盖整个窗口。关闭状态下的透明原生像素绝不覆盖 Harness 或官方 Chat 控件。

在 macOS 上，控件从 x=88 开始，紧跟红黄绿按钮组右侧。在 Windows 上，它从 x=12 开始，原生标题按钮仍位于右侧。控件从 y=6 开始，在 44px 标题栏中垂直居中。调整窗口大小时会重新计算控件与 Chat 菜单边界，但不会改变标签、加宽可见切换器或裁剪菜单。

shell 拖拽区域从标题栏控件最大占用范围之后开始：macOS 为 x=300，Windows 为 x=224。它的原生命中测试矩形绝不与切换器或 Chat 溢出控件重叠。mode chrome 只把实际交互控件标记为不可拖拽。CSS、Electron 边界计算和测试共享这项几何不变量，防止 shell 拖拽层截获发往切换器的原生指针输入。

切换器无需展开几何状态：任一分段都通过关闭状态的 IPC 命令直接发送选中模式。打开 Chat 操作菜单仍是一次需要确认的几何状态转换。renderer 请求展开状态，主进程调整 WebContentsView 边界并返回已应用状态，renderer 只有在收到该确认后才显示菜单。关闭时先隐藏菜单，再让视图恢复紧密边界。失去焦点、按下 `Escape`、执行命令或收到陈旧确认时，都不会在产品内容上方留下不可见的展开视图。

44px 标题栏底色属于已有的操作系统标题栏，不是额外的应用行。Chat 模式下，它跟随 Chat 解析后的亮色或暗色配色，并使用对应的页面背景色，不带分隔线、透明效果或 vibrancy 色偏。因此页面与标题栏呈现为连续表面。Harness 保留现有标题栏合成方式。

shell 文档在内容视图后方保留，用于加载和失败状态。选中视图就绪后，其内容覆盖对应内容区域；加载中或失败时，shell 状态区可见，同时模式选择器保持可交互。

## 共享主题偏好

同步的主题偏好包含 `light`、`dark` 和 `system`。桌面主题协调器在内存中保存当前偏好和解析后的亮／暗配色。当前模式拥有决定权：可见模式报告的偏好变化会更新协调器并发送给隐藏模式；隐藏模式的报告只作为确认，不能覆盖当前偏好。

启动时，初始选中模式在主题桥就绪后提供权威偏好。另一模式在变为可见前采用该值。如果两个页面持久化的偏好不同，这条规则无需时间戳或额外持久主题存储即可解决冲突。当共享偏好为 `system` 时，操作系统变化会更新两个渲染器与本地 chrome，但不会改变持久化偏好。

模式切换器、Chat 溢出控件和标题栏底色跟随协调器解析出的配色。亮色使用深色文字，暗色使用浅色文字。切换器高亮、Chat 菜单和对话框使用不透明主题表面，因为其文字必须在任意内容上方保持可读。

## Harness 主题桥

Harness 使用一个只附加到本机回环桌面渲染器的自有主题桥。该主题桥发布 `ThemeRuntime` 偏好及解析后配色，接收一个经过验证的共享偏好，并通过 `ThemeRuntime.setTheme()` 应用。Harness 的常规持久化仍由 Host 支持的主题设置作用域负责。

Electron 只暴露 Harness 客户端所需的封闭主题操作。主题桥不暴露 Electron 原语、文件系统访问或通用 IPC。没有桌面标记的普通浏览器用法保持不变。

现有 `meta[name="theme-color"]` 事件继续作为合成信号和后备诊断，但不再承担同步协议，因为它只携带解析后的颜色，无法区分 `system` 与具体偏好。

## Chat 主题适配器

DeepSeek Chat 没有公开的桌面主题 API。因此，隔离的 Chat preload 为官网当前主题表示持有一个带版本的私有适配器。它只读写 `__appKit_@deepseek/chat_themePreference` 存储项及经过验证的 `{ value, __version: "0" }` 包装，观察页面的 `light`／`dark` body 状态以确认解析后配色，并把页面顶部或根节点的一个不透明计算背景规范化为标准 `#rrggbb`，供已有标题栏底色使用。主进程会拒绝透明、格式错误和任意 CSS 值。适配器绝不读取账号、会话、草稿、令牌、消息或其他页面内容数据。

## Chat 启动侧栏状态

官方 Chat 在零版本 `__appKit_@deepseek/chat_lastSessionValue` 存储项中保留侧栏选择。隔离 preload 会在每个 Chat document 初始化前，只把 `value.siderCollapsed: true` 改为 `false`，并保留其他所有设置。存储项缺失时沿用网站的展开默认值；版本或表示形式未知时不修改原值，并报告适配器诊断。该行为只设置启动默认值，不会持续强制展开：document 加载后，用户可以收起侧栏，保留的视图会在模式切换期间维持该状态。preload 绝不会定位或点击远程 DOM 控件。

Chat 处于活动状态时，官网主题变化会报告给桌面协调器，并通过自有主题桥应用到隐藏的 Harness。Harness 处于活动状态时，变化后的偏好会写入隐藏的 Chat；Chat 在隐藏时重载，使官网应用状态与设置界面在下次模式切换前采用相同偏好。适配器绝不会因为隐藏模式的报告而重载可见 Chat。

Chat preload 不向远程页面暴露 IPC 或 context-bridge 对象。它在接受或应用偏好前验证预期存储包装和页面标记。遇到未知存储版本、缺失主题标记或更新被拒绝时，该渲染器的 Chat 同步会停止，并只报告一次诊断。Chat 的认证、导航、会话和普通主题控件仍由官网负责并继续工作。

## 状态与生命周期

没有持久模式选择时，Harness 仍是初始模式。选中模式通过现有桌面状态文件持久化，并在下次启动恢复。主题仍由两个产品各自现有的偏好所有者持久化；协调器只决定当前应用会话内的同步顺序。

控制器继续延迟创建 Chat、在隐藏时保留健康视图、在重试时重建失败视图，并隔离两种模式的失败状态。创建或重建视图时，会在视图变为可见前接入其主题桥，防止首次显示相反主题。

清除 Chat 数据会随专用分区中的其他数据一并删除官网持久主题。重建后的选中 Chat 视图会在变为可见前采用当前共享偏好。

## 验证

单元测试覆盖协调器启动权威来源、三种偏好、活动模式向隐藏模式传播、确认回环抑制、`system` 下的操作系统更新、主题桥释放、格式错误的 Chat 存储、未知版本、规范化的不透明背景色、任意 CSS 值拒绝和适配器故障隔离。

Electron 集成测试使用真实 WebContentsView 证明两个同步方向、仅隐藏状态重载 Chat、选中模式冲突裁决、清除 Chat 数据后的主题恢复、用真实指针选择两个分段、切换器键盘行为、Chat 菜单展开和关闭、Chat 状态保留、失败隔离和重试。

Chat fixture 在页面的原始内容原点提供一个左上侧栏控件。mode chrome 关闭时，真实指针点击必须到达该控件。原生边界断言证明拖拽区域与 chrome 矩形绝不重叠，Chat 只使用操作系统标题栏 inset，并且 chrome 只在 Chat 菜单或对话框打开时扩展。

使用空 user-data 目录的 Electron 运行必须从 Harness 启动。选择 Chat 后使用同一目录重启时，必须恢复 Chat。随后场景直接选择 Harness，以证明打包交互路径中的两个分段始终可点击。

样式与截图检查覆盖 macOS 和 Windows 标题栏几何、亮暗前景色、无外框的等宽分段、稳定的 `Chat | Harness` 标签、匹配的 Chat 页面与标题栏背景、不存在应用自有标题区、Chat 菜单、加载与失败状态、拖拽区域和减少动画。

打包运行时检查确认本地 shell、mode chrome、Harness 主题桥、隔离 Chat preload、Chat WebContentsView 入口、Harness Host 入口和 Web 前端同时存在于 macOS 与 Windows 产物中。

## 备选方案

### 仅使用应用自有主题控件

桌面独立偏好可以通过操作系统媒体信号驱动两个页面，但在官网 Chat 设置中作出的明确选择无法更新 Harness，因此不能提供双向同步。

### 自动操作官网设置控件

打开 Chat 设置对话框并点击主题选项可以复现用户手势，但会依赖私有 DOM 结构、翻译文案、焦点时序和动画状态。带版本的存储适配器依赖更少，并且可以在不操作远程界面的情况下失效。

### 独立的应用自有标题区

在 Chat 上方放置本地选择器行可以分开控件，但会减少页面高度、呈现为第二条工具栏，并让 Harness 与 Chat 从不同的视觉高度开始。操作系统标题栏已经提供所需的共享控件行。

### 下拉式产品选择器

文字标签加下箭头占用的标题栏宽度更小，但每次切换模式都必须先打开菜单，控件也无法持续展示两个选项。直接双分段切换器操作更快、能够呈现当前可选模式，并移除了此前让原生命中测试更复杂的展开式模式菜单层。

### 把选择器注入两个产品

在两个导航树内渲染选择器可以使其对齐局部控件，但 Chat 会依赖远程私有 DOM 和 CSS，两种模式也会各自持有一套重复交互实现。本地标题栏视图可以保持远程页面不变，并让一个控制器拥有决定权。

### 原生应用菜单

只把模式选择放入操作系统菜单可以避开 Web 内容分层，但不易发现，并且 macOS 与 Windows 的表现差异很大。

## 不在范围内

设计不合并 Chat 会话与 Harness 会话、不同步凭据、不向 Harness 暴露 Chat 私有 API、不检查主题状态之外的 Chat 内容、不增加第二个应用窗口，也不承诺兼容官网未来未带版本的主题表示。
